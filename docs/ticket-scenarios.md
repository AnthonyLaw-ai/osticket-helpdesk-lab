# Ticket Scenario Summary

This document summarises the simulated tickets completed in the osTicket lab.

| Scenario | Category | Troubleshooting / Action | Result |
|---|---|---|---|
| Account access issue | Identity & access | Reviewed account status and permissions, corrected access | Resolved and closed |
| Account lockout | Identity & access | Verified user, checked lockout, unlocked account | Resolved and closed |
| Wi-Fi connectivity | Networking | Isolated issue to one laptop, checked adapter/configuration, recreated Wi-Fi profile | Resolved and closed |
| Outlook not opening | Applications | Tested in Safe Mode, isolated problematic add-in, disabled add-in | Resolved and closed |
| Network printer not printing | Hardware / Windows services | Cleared print queue, restarted Print Spooler, test printed | Resolved and closed |

## Support Workflow Used

For each scenario, the same professional lifecycle was followed:

1. Create or identify the user.
2. Log the issue with a clear summary and description.
3. Select source, help topic, department, SLA, priority, and assignee.
4. Send an initial acknowledgement to the user.
5. Investigate and document the technical work in an internal note.
6. Verify the issue is resolved.
7. Send a clear user-facing resolution.
8. Close the ticket.
